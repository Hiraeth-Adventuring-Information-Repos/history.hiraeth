## 2024-05-01 - Optimizing Timeline Rendering by Caching Data and DOM Elements
**Learning:** High-frequency event handlers (like debounced search inputs) must be extremely lightweight. Redundantly iterating over and sorting large datasets, as well as repeatedly querying the DOM (`document.querySelector`), within these handlers can cause severe jank and sluggish UI updates. In this codebase, the timeline rendering function `renderTimeline` was doing both for every keystroke.
**Action:** When working with frequently updated UI components, pre-calculate and cache static or semi-static data (like the chronically sorted events per era). Similarly, pre-fetch and cache references to necessary DOM containers instead of repeatedly querying them. Pass these cached structures into the rendering function to ensure it only performs the necessary filtering and HTML generation, keeping the main thread free.
